# LendLoop

> Borrow what you need. Lend what you don't.

A neighborhood tool-lending board. Neighbors list tools, request to borrow them for a date range, and get notifications and overdue reminders handled by n8n.

**Stack:** Next.js 15 (App Router) · TypeScript · Clerk · Convex · n8n · Tailwind CSS · Vitest

## Features

| Area | What it does |
| --- | --- |
| Public page | Tagline, read-only list of **available** tools (name and category only), "Sign in to lend or borrow" button |
| All tools | Every tool with its availability, filterable by category; request to borrow for a date range |
| My listings | Create, edit and delete your own tools |
| My requests | Your borrow requests; withdraw a pending one, mark an approved one as returned |
| Incoming requests | Requests for your tools; approve, decline, mark returned |
| Admin | Remove any listing, view all loans, grant or revoke **Trusted Lender**, see failed automation runs |
| Automation | Notifications on every request status change; daily overdue reminders; activity shown on each loan ("Reminder sent 2 days ago") |

### Loan lifecycle

```
            request              approve                 mark returned
 (none) ──────────────▶ pending ─────────▶ approved ────────────────────▶ returned
                          │  │
                 decline  │  │ withdraw (borrower)
                          ▼  ▼
                    declined  cancelled
```

Every transition is validated on the server: only the lender can approve or decline, only while the request is `pending`, and an approval is rejected if its dates overlap another approved loan for the same tool.

## Architecture

```
┌──────────────┐  Clerk JWT  ┌────────────────────────────┐  signed webhook  ┌─────────────────────┐
│  Next.js UI  │────────────▶│ Convex                     │─────────────────▶│ n8n                 │
│  (Clerk)     │◀── live ────│  queries / mutations       │                  │ 1. Request notif.   │
└──────────────┘   queries   │  (all access rules here)   │◀─── signed ──────│ 2. Overdue reminder │
                             │  HTTP actions /n8n/*       │   GET + POST     │ 3. Error handler    │
                             └────────────────────────────┘                  └─────────────────────┘
```

| Path | Responsibility |
| --- | --- |
| `convex/schema.ts` | Tables: `users`, `tools`, `loans`, `automationEvents` (with indexes) |
| `convex/lib/auth.ts` | `requireUser` / `requireAdmin`: identity always comes from the verified JWT |
| `convex/tools.ts`, `convex/loans.ts`, `convex/users.ts` | Public API with ownership and role checks |
| `convex/notifications.ts` | Outbound signed webhook to n8n, with retries and failure recording |
| `convex/automation.ts`, `convex/http.ts` | Inbound endpoints for n8n: overdue loans and idempotent write-backs |
| `convex/lib/signature.ts` | HMAC-SHA256 signing and verification shared by both directions |
| `src/app/*` | Pages: `/`, `/tools`, `/listings`, `/requests`, `/incoming`, `/admin` |
| `n8n/workflows/*.json` | Exported workflows (generated by `scripts/build-workflows.py`) |

**Key decision: authorization lives in Convex, not in the UI.** The Next.js middleware only redirects signed-out users away from private pages. Every Convex function checks identity, ownership and role on its own, so calling the API directly cannot bypass a rule. The tests call those functions directly to prove it.

## Local setup

**Requirements:** Node.js 22+, Docker, a Clerk account and a Convex account (both have free tiers).

### 1. Install and start Convex

```bash
npm install
npx convex dev          # creates the deployment and writes .env.local
```

### 2. Configure Clerk

1. Create a Clerk application and copy its keys into `.env.local` (see `.env.example`).
2. Connect Clerk to Convex with **one** of these options:
   - **Convex integration** (Clerk dashboard → Integrations → Convex → Activate). Then open **Configure → Sessions → Customize session token** and make sure the claims include the user's name and email:
     ```json
     {
       "aud": "convex",
       "name": "{{user.full_name}}",
       "email": "{{user.primary_email_address}}",
       "nickname": "{{user.username}}"
     }
     ```
   - **JWT template**: **Configure → JWT templates → New template → Convex**, and keep the name `convex`.

   The email claim is required: the admin role is derived from it.
3. Copy the **Issuer** URL (your Clerk Frontend API URL) and set it on Convex:

```bash
npx convex env set CLERK_JWT_ISSUER_DOMAIN https://<your-app>.clerk.accounts.dev
npx convex env set ADMIN_EMAILS you@example.com     # comma-separated list
```

### 3. Start n8n

```bash
cp .env.n8n.example .env.n8n     # set LENDLOOP_SHARED_SECRET and CONVEX_SITE_URL
docker compose up -d
docker compose exec n8n n8n import:workflow --separate --input=/workflows
```

Open <http://localhost:5678>, then activate **LendLoop – Request notification** and **LendLoop – Overdue reminders**. The error handler runs automatically and does not need to be activated.

Point Convex at n8n with the same shared secret:

```bash
npx convex env set N8N_SHARED_SECRET <same value as LENDLOOP_SHARED_SECRET>
npx convex env set N8N_WEBHOOK_URL <public URL of n8n>/webhook/lendloop/loan-events
```

> **Networking note.** A Convex cloud deployment cannot reach `localhost`. To use cloud Convex with local n8n, expose n8n through a tunnel (for example `cloudflared tunnel --url http://localhost:5678`) and use that URL for `N8N_WEBHOOK_URL`. For n8n to reach Convex, `CONVEX_SITE_URL` is your deployment's `https://<name>.convex.site` URL. Alternatively, choose a **local** deployment when `npx convex dev` asks for one: Convex then reaches n8n at `http://localhost:5678`, and n8n reaches Convex at `http://host.docker.internal:3211`.

### 4. Run the app

```bash
npm run dev     # http://localhost:3000
```

Sign in with the email listed in `ADMIN_EMAILS` to see the Admin area.

## Security and data minimization

### Authentication and authorization
- **The server derives identity.** Functions resolve the user from the verified Clerk JWT (`ctx.auth`) and never accept a user id from the client.
- **The server assigns roles.** Admin comes from `ADMIN_EMAILS` on the Convex deployment and is re-derived on every sign-in, so removing an email revokes the role. The client has no way to set its own role.
- **Ownership is checked in every mutation.** Only the owner can edit a listing. The owner or an admin can delete it. Only the lender decides on a request, only the borrower can withdraw one, and only the two parties of a loan can mark it returned.
- **State transitions are validated.** A decided request cannot be decided again, overlapping approvals are rejected, dates are validated, and a borrower cannot request the same tool twice for overlapping dates.

### Data minimization
- **The public page** returns only `name` and `category` of available tools. No owner, condition, description or loan data.
- **Signed-in users** see the other party's display name and the Trusted Lender badge. Emails are never sent to the browser, except to admins.
- **Webhooks to n8n** carry only what one notification needs: first name, email of the single recipient, tool name, dates and status.
- **The overdue endpoint** returns the same minimal fields per loan, and only for loans that are actually overdue and not yet reminded that day.
- **Automation events** store a status and a short detail, never message content or personal data.

### Integration security
- **Both directions are HMAC-SHA256 signed.** The signed message is `"<timestamp>.<raw body>"`. Requests older than five minutes are rejected, which limits replay, and signatures are compared in constant time.
- **n8n verifies the raw bytes** Convex signed, not a re-serialized object, so JSON key order cannot break or bypass verification.
- **Inbound bodies are validated strictly** with Zod (`.strict()`): unknown fields are rejected, and an `idempotencyKey` must match its `kind`.
- **Error responses are generic** (`401 unauthorized`). The specific reason is only logged on the server.
- **Secrets stay out of code.** They live in environment variables (Convex dashboard and `.env.n8n`), and workflows read them through `$env`. A test fails if a secret, credential or key ever appears in the exported workflow JSON.

## n8n integration

### Workflows

| Workflow | Trigger | Steps |
| --- | --- | --- |
| **Request notification** | Webhook `POST /webhook/lendloop/loan-events` | Verify signature → 401 if invalid → notify the recipient (logged mock) → signed write-back to Convex → 200 |
| **Overdue reminders** | Schedule, every day at 09:00 | Signed `GET /n8n/overdue-loans` → one item per loan → send reminder (logged mock) → signed write-back |
| **Error handler** | Error Trigger | Records the failure in Convex as a `workflow_error` event, shown in the Admin area |

Notifications are logged mocks, which the brief allows. In production you would replace the two `(mock)` Code nodes with an Email, Slack or Discord node; nothing else changes.

### Reliability
- **Idempotency.** Every logical event has a stable key: `request_notification:<loanId>:<status>` and `overdue_reminder:<loanId>:<date>`. `POST /n8n/events` stores each key once, so a retried write-back returns `duplicate: true` and creates nothing. A later `sent` upgrades an earlier `failed`.
- **No duplicate reminders.** The overdue endpoint skips loans already reminded that day, so re-running the scheduled workflow does not remind anyone twice.
- **Retries on both sides.** In n8n, every HTTP node retries 3 times with a 3-second wait. In Convex, the outbound webhook retries with exponential backoff (1s, 2s, 4s) through the scheduler.
- **Nothing fails silently.** When Convex runs out of retries, it records a `failed` event. When an n8n workflow fails after its retries, the error workflow records it. The Admin area lists both.

### Editing the workflows

The JSON exports are generated from `scripts/build-workflows.py`, so the signing code is reviewable in one place and secrets cannot leak into an export:

```bash
python3 scripts/build-workflows.py
```

## Tests

```bash
npm test          # Vitest: 24 tests
npm run typecheck
npm run lint
npm run build
```

| File | What it proves |
| --- | --- |
| `convex/rules.test.ts` | Access rules run against the real Convex functions (via `convex-test`): ownership, admin-only actions, transitions, overlapping approvals, date validation, and that the public listing and catalog leak no owner data |
| `convex/integration.test.ts` | HMAC verification (tampering, wrong secret, stale timestamp), the overdue endpoint's minimal fields and once-per-day behavior, idempotent write-backs, strict body validation |
| `n8n/workflows.test.ts` | Runs the **actual Code node scripts** from the exported workflows and checks they interoperate with Convex in both directions; asserts no secrets or credentials are exported and that every workflow has retries and an error workflow |

## What I would change for production

1. **Real notifications.** Replace the mock Code nodes with an email provider (for example Postmark or SES) and keep the same minimal payload.
2. **Durable, observable delivery.** Use the Convex Workpool or a queue for outbound webhooks, and alert on `failed` automation events (Sentry or Datadog) instead of only listing them.
3. **Secret management and rotation.** Store the shared secret in a secrets manager, support two active secrets during rotation, and use a separate secret per direction.
4. **Roles managed in Clerk.** Move roles to Clerk organizations or public metadata included in the JWT, with an audit log of role and Trusted Lender changes.
5. **Timezones.** Store each user's timezone and compute "today" and "overdue" per user. Today the server uses UTC with one day of tolerance.
6. **Scale.** Paginate the catalog and admin lists, and denormalize availability onto `tools` instead of computing it from loans on every read.
7. **Abuse protection.** Add rate limits on request creation and on the `/n8n/*` endpoints, restrict those endpoints by network where possible, and add moderation for listings.
8. **n8n hosting.** Use Postgres instead of SQLite, encrypted credentials (`N8N_ENCRYPTION_KEY`), queue mode for workers, and n8n behind TLS with the webhook path restricted.
9. **Privacy.** Define a retention policy for loans and automation events, and add account deletion that anonymizes loan history.
10. **CI.** Run lint, typecheck, tests and `npx convex codegen` checks on every pull request, plus Playwright end-to-end tests of the main flows.
